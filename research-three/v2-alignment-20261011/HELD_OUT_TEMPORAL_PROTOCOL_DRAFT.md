# 独立 held-out 时序研究协议草案

**状态：** 草案；未注册、未执行、未纳入新数据。本文不冻结生产规则、业务阈值、样本量或多 flag severity 策略。

## 研究目的

在独立、按时间排序且经过外部裁决的证据轨迹上，比较逐关联提醒与候选同卡更新策略。评价重点是重要提醒漏报/迟报、不同物理事件被误合并、同一物理事件被误拆分，以及事件关联保持未决的时长。策略输出只作为软件决策记录；本协议不调用真实模型、不投递通知，也不把软件决策时间当作用户可见时间。

本分支的 23 条合成输入和其派生结果只属于开发证据，不能进入 held-out 集、调参集或独立样本分母。

本文前半部保留原草案的指标与盲态约束作为历史规格；2026-10-11 结果驱动修订段落是下一版的评分与实施入口。原失败结论和旧指标不回填或改写。

## 盲态与数据隔离

1. 数据保管方先按物理事件/来源根、设备或资产、任务、站点和时间块去重，再按独立组切分开发集与 held-out 集；同一物理事件的相邻片段、重复到达、重放副本及派生记录必须留在同一分区。
2. held-out 的真值、事件簇 ID、场景类别、场景 ID、oracle 动作标签、人工复核结论和未来证据不进入被测策略。策略只接收按当时可用顺序呈现的观测、来源/设备/任务绑定、可用时间、公开风险标记及实际可见的证据属性。
3. 风险标记是当时可见的输入证据；`RISK_ESCALATION`、`EVENT_SPLIT`、`CONFIRM_NEW` 等裁决标签是结果，不能作为被测策略的输入。用于配对运行的随机轨迹键由评测包装层持有，策略接口不暴露它，也不暴露任何语义场景 ID。
4. held-out 开封前冻结输入适配器、策略代码和参数、公开单 flag 映射、评分程序、排除规则、分析脚本及提交 SHA。开发人员不能根据 held-out 结果修订策略后仍将同一分区称为 held-out。
5. 两名独立裁决者依据证据与时间线标注，彼此盲态且不查看策略输出；分歧由第三名裁决者处理。真值与合格证据的裁决存于 scorer-only 区域，运行完成后才按不透明轨迹键联接。

## 必须覆盖的时间模式

held-out 采样框应覆盖以下模式；它们只描述抽样维度，不成为策略可见标签：

- **事件重启：** 一个有独立边界证据支持的事件终结后，后续风险再次出现；裁决持续原事件、重新开启或新事件。
- **合格新证据：** 新来源或观测在其合法 `known_time` 到达；评分只在策略确实可知之后评估，不允许用事后 `source_time` 提前触发。
- **设备/任务重绑定：** 设备身份、任务绑定或其有效时间发生变化；保留旧绑定历史，并由独立裁决确定关系是否仍可持续。
- **冲突变化：** 关系由未知转冲突、冲突加重/缓解、冲突解决或再次出现；保留每次转换及其可知时间。
- **无动作标签的单 flag 升级：** 输入风险标记从公开映射为 `WARNING` 的单 flag 变为公开映射为 `CRITICAL` 的单 flag，不提供 `RISK_ESCALATION` oracle 标签。另设同等级与单 flag 降级控制。

多 flag 汇总规则尚未冻结。该类记录可按预注册的未知/待核状态分层报告；不得排序、最大值聚合或用它们训练单 flag 升级判别器。当前输入接口不支持 `task_ids`，因此重绑定轨迹在接口与绑定合同可用、并经预注册后才可进入策略比较；在此之前只能报告为不可评价，不得伪造 task ID。

## 比较条件和运行

- 至少包括逐关联提醒基线和待评估的卡片合并策略；若另加策略臂，需在 held-out 开封前写入注册表。
- 每个策略接收同一轨迹的相同前缀序列；输入序列只包含该处理时刻已知的信息。重放、重复到达和迟到证据按真实到达时间进入，不重排为事后理想顺序。
- 配置中的合并键、窗口、风险阶段处理、单 flag 触发逻辑、无效/未知证据处理均须在开封前由研究负责人冻结并记录来源。当前 0/5 秒窗口仅为既有开发参数，不自动成为 held-out 配置。没有明确规则时，该维度标记为待定并停止相应比较。
- 只运行离线、无副作用的策略决策；记录生成的提醒内容、卡片修订、动作/关联状态及内部决策时间。所有 `emitted_at`、真实送达与 `visible_at` 结果保持未运行；不得向用户或设备发送通知。

## 主要评价量

分别报告下列指标及其分子、分母和不可评价数量，不合成单一总分：

1. **重要提醒漏报率：** 分母为独立裁决确认存在应提醒机会的轨迹/前缀；分子为策略未在预注册评价窗口内产生相应重要更新的机会。逐机会保留误差归因，不把重复方法行计为样本。
2. **重要提醒迟报：** 按独立裁决确定的首次可知触发时间与策略内部首个对应决策时间计算连续延迟分布；同时报告漏报与迟报分布。绝不将内部决策时刻解释成真实 emitted/visible 时间。任何 deadline/SLO 阈值须在开封前另行冻结；本草案不设数值。
3. **错误合并：** 对独立裁决为不同物理事件、但策略把候选/关系置于同一事件身份组的配对计数和比例。以裁决认定可比较的候选对为分母，并给出按新证据可用时间的错误发生窗口。
4. **错误拆分：** 对独立裁决为同一持续事件、但策略无合格边界仍建立互不链接的独立事件身份的计数和比例。卡片展示上下文不同不自动定义为物理事件拆分；按事件身份输出评分。
5. **未决时长：** 从策略首次进入 `UNKNOWN_PENDING`/`CONFLICT_PENDING` 的可知时刻，到独立裁决支持的解析状态首次出现之时；研究结束仍未解决的轨迹按右删失报告。给出分布和删失比例，不能把数据结束当成已解决。

附加负担指标可记录首报、更新、重放与合并动作数，但不得抵消漏报、错误合并/拆分或更长未决时长。统计单位是独立轨迹或事件簇；区间估计按站点/设备/物理事件簇处理相关性。样本量和检验方法由独立统计计划在数据来源和最小重要差异确定后冻结。

## 预注册前必须解决的事项

- 可合法使用且可追溯的 held-out 数据来源、权限、覆盖时间与独立事件分母；
- `task_ids`/设备绑定接口与时态有效区间合同；
- 来源资格及“合格新证据”的裁决标准；
- 待测策略的合并键、时间窗、无效证据与多 flag 的待核处理；
- 重要提醒机会定义、首次可知时间、deadline/SLO（若要报告阈值型及时性）；
- 同一事件持续、重启、结束、新事件、误合并/误拆分的独立真值流程；
- 轨迹数量、排除条件、删失处理、统计分析和多重比较计划。

在这些决定和接口满足前，本文件仅供评审。它不是运行授权、业务规则、正式统计计划、真实通知试验或 Mac 资格验证；不得根据该草案宣称效果成立。

## 2026-10-11 结果驱动修订：先隔离提醒动作策略

本节是按既有失败结果修订的评估规格，不改写旧试验、不重跑旧试验，也不把修订规格冒充预注册或结果。Mac V3-RSS 单次试验的历史摘要仍记录为整轮失败：1464 项检查执行完成，但五个合成场景、四种方法都没有确证新事件首报（20 条方法记录不是独立样本）。此结论不由本分支代码验证或推翻。

### 分阶段与共同前缀输入

第一阶段只比较提醒动作策略。一个冻结的上游轨迹生成器按每个可见处理时刻生成前缀，物化一次后，将同一不可变前缀对象提供给逐关联提醒和同卡更新两臂。每个字段值须携带生成者与最早可知时间，至少包括 `kind`、`association_state`、`display_card_id`、`candidate_episode_ids`、`dedup_episode_interval_key`。策略不得接收未来后缀、scenario ID、oracle 动作或事后事件真值。稳定的 `display_card_id` 只表示界面连续性，不等于事件身份；候选 episode 保持为独立节点，`UNKNOWN_PENDING` / `CONFLICT_PENDING` 不可自动推成同一事件。冲突可先产生待核实风险提醒；同一展示卡后续持续更新；身份有充分证据且符合冻结规则后，才确认关系或创建独立新卡，并保留到原卡的历史链接。

本地最小适配器位于 [`frozen_prefix_adapter.py`](../../risk-fusion-bench/src/rfb/research/frozen_prefix_adapter.py)，用例位于 [`test_heldout_prefix_adapter.py`](../../risk-fusion-bench/tests/test_heldout_prefix_adapter.py)。`PrefixFieldFact` 记录字段值、声明的 producer、`earliest_known_at` 与 evidence refs；`freeze_visible_prefix` 只选 `as_of` 时刻可见的最新字段版本，同时间冲突值会失败关闭。它不验证 producer 的真实性、推断身份、定义业务阈值或读取 scorer 真值。适配器只提供阶段一的数据边界；端到端事件识别与确证仍未实现或评价。

纯软件身份转移函数位于 [`event_card_resolution.py`](../../risk-fusion-bench/src/rfb/research/event_card_resolution.py)，focused 用例位于 [`test_event_card_resolution.py`](../../risk-fusion-bench/tests/test_event_card_resolution.py)。它把外部提供且带证据时间的 `DIFFERENT_CONFIRMED` 映射为原卡/新卡两个身份记录和双向历史链接；新卡 ID 必须由调用方稳定提供。`UNKNOWN_PENDING` / `CONFLICT_PENDING` 期间只保留两个候选 episode，不做身份合并；`SAME_CONFIRMED` 才在现有卡保留两个 episode 引用。函数不推断确证、不产生用户文案或执行投递。提醒动作台账仍未接入这个身份转移结果，完整卡片渲染与真实用户可见性仍待实现和评价。

对同一前缀替换任意未来后缀，两个策略臂的冻结输入与策略形状都应保持一致。对所有随机 ID 做一致重命名，策略输出的计数、状态与关系结构应保持同构，仅相应 ID 改变。ID 同构只检查策略对标识符不敏感，不说明事件关系正确。适配器测试输入是显式合成值，不纳入数据集、独立样本分母或效果估计。

### 拆分、确认与未决时间的评分

- 错误拆分按独立裁决的物理事件身份簇计分：真值同一事件却被策略确认为 `DIFFERENT_CONFIRMED` 或生成互不链接的事件身份，记为错误；到旧卡的历史链接不能抵消错误身份判定。卡片展示分离与事件身份拆分分别记录。
- 错误合并按真值不同的物理事件对计分：策略将其确认为同一事件身份才记为错误。候选 episode 重叠、卡片相同或提醒被合并，单独都不能证明物理事件被合并。
- 每段待确认轨迹分别记录 `t_pending`（首次进入待确认的策略可知时间）、`t_evidence_sufficient`（独立裁决认为足以解析的证据首次可知时间）、`t_policy_valid_resolution`（策略第一次在证据门槛已满足后给出合规的有效解析）。报告证据尚未充分阶段 `t_evidence_sufficient - t_pending` 与证据充分后阶段 `t_policy_valid_resolution - t_evidence_sufficient`。
- 错误确认不会结束未决时长；只有符合预先冻结证据门槛且身份结论正确的策略结果才可记作有效解析。截止仍未进入充分证据阶段的记录，对第一阶段右删失；已有充分证据但未有效解析的记录，对第二阶段右删失。截止时间须随独立轨迹一并冻结。

### 三项分别报告的结果

1. **提醒及时性**：每个独立裁决确认的重要提醒机会，从该机会最早 `known_time` 到策略首个对应的合规内部决策时间，按机会报告漏报和连续延迟分布。内部决策时间不代表 emitted、送达或用户可见时间。真实送达能力不可用时，投递结果明确标为 `NOT_DELIVERED` 或 `SIMULATED`，不将模拟时间算入真实及时性。
2. **内容完整性**：按冻结的公开 V2 字段合同和每次完整的用户可见卡片渲染，逐字段评估必需字段、引用、当前关系状态、历史链接与版本一致性。增量更新预览、存在性检查和“卡片修订已记录”不等于完整卡片被显示；无真实完整渲染/送达凭据时标为不可评价，不能判 PASS。
3. **事件确证准确性**：按独立物理事件簇与前缀时点分别报告 SAME/DIFFERENT/UNKNOWN/CONFLICT 的混淆计数、覆盖率，以及错误合并、错误拆分。待确认状态可作为拒判/未决覆盖报告，不能算作确证正确；只报提醒动作数不足以评价此项。

三项不得合成单一总分，也不得彼此抵消。原 1464 检查口径、原严重性与旧运行指标继续保留为历史记录；这次修订是结果驱动的下一版规格，不回填新分数。

### 盲态、切分与数据可得性盘点

按物理事件/轨迹簇做互斥开发与 held-out 切分；相关设备、任务、来源根、站点、重放副本及邻接片段须按预注册规则成组，不能跨分区。评分方可以查看完整轨迹确认结局，但应逐前缀裁决每项证据最早何时可知。AI 预标注单独存放并记录模型、版本、提示与处理时间；两名人工裁决者在看不到 AI 预标、策略输出及对方判断的情况下独立裁决，分歧交第三人处理。AI 预标和用户复核均不自动成为真值或策略输入。

### 下一阶段入口

先完成真实/公开轨迹的权限与可追溯性核验，以及独立事件真值和逐前缀 `known_time` 标注计划；再冻结任务/设备时态绑定输入接口、完整卡片渲染合同、三项指标分母与删失分析、两臂参数和切分 SHA。其后只对冻结 prefix adapter 和隔离动作台账做合成性质测试。数据、接口与人工盲审流程均满足后，才能单独注册并申请执行 held-out 评估。Mac ESRCH/EPERM 退出原因尚未确诊；云端协议、单元测试和代码通过都不能作为 Mac 修复验证。
