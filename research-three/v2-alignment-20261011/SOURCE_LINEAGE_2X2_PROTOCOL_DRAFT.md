# Source-Lineage 2×2 Comparison — Protocol Draft

- **Status:** `DRAFT_NOT_RUN`; reviewable input protocol only.
- **Protocol ID:** `source-lineage-observability-2x2-v1.0.0`.
- **Scope:** four literal synthetic assignments, two unique visible graph inputs, pure CPU only. No held-out split or effect estimate.
- **New contract under study:** `source_lineage_contract_v1.assess_source_lineage`.

## Factors and interpretation

The crossed factors are (1) scorer-only event relation (`SAME` / `DIFFERENT`) and (2) visible lineage graph relation (`SHARED_KNOWN_ANCESTOR` / `NO_SHARED_KNOWN_ANCESTOR` under complete, verified, time-valid graph evidence). Every case uses two distinct declared root-ID strings. This makes the graph, not root-ID count, the observed provenance evidence.

For each graph relation, the SAME and DIFFERENT cases use byte-identical method-visible input. Event relation is generated by a predeclared scorer-only event registry and is not inferred or scored. The source-family label, if retained in the scorer ledger for fixture auditing, never enters method input. The visible input contains only explicit lineage nodes, directed edges, evidence references, evidence times, completeness declarations, and trust states.

`NO_SHARED_KNOWN_ANCESTOR` remains a bounded graph observation, not statistical independence. The comparison may check that shared ancestry is grouped and incomplete or invalid ancestry remains unknown. It may not report improved event recognition or claim that disjoint known graphs are independent.

## Four registered assignments

| Case | Hidden event relation | Visible graph input | Clone | Expected contract output | Event scoring |
|---|---|---|---|---|---|
| `LS-SAME` | SAME | Two distinct root IDs; complete verified graph with an evidenced shared upstream node | `LS-DIFF` | `SHARED_KNOWN_ANCESTOR`; return the shared node for evidence grouping | Not scored; clone is byte-identical |
| `LS-DIFF` | DIFFERENT | Exact same bytes as `LS-SAME` | `LS-SAME` | Same contract result as `LS-SAME` | Not scored; clone is byte-identical |
| `LD-SAME` | SAME | Two distinct root IDs; complete verified graph with no shared known ancestor | `LD-DIFF` | `NO_SHARED_KNOWN_ANCESTOR`; never `INDEPENDENT` | Not scored; clone is byte-identical |
| `LD-DIFF` | DIFFERENT | Exact same bytes as `LD-SAME` | `LD-SAME` | Same contract result as `LD-SAME` | Not scored; clone is byte-identical |

The two visible graph templates are literal and deterministic. The exact graph nodes and edges, evidence references, timestamps, trust state, and canonical byte hashes must be frozen before any contract call. The scorer-only event registry and any synthetic source-family audit stay in a separate file, opened only after output bytes are frozen.

### Literal template shape to freeze

Both graph templates use observation IDs `OBS-A` and `OBS-B`, cutoff `2026-10-11T12:02:00Z`, and distinct declared roots `ROOT-A-01` and `ROOT-B-01`. Every node, edge, and completeness claim carries a `synthetic://lineage/<claim-id>` source reference, `actual_available_at=2026-10-11T12:00:00Z`, `earliest_known_at=2026-10-11T12:00:00Z`, `trust_status=VERIFIED`, and `valid_until=2026-10-11T12:10:00Z`.

| Template | Nodes | Directed edges | Completeness |
|---|---|---|---|
| `VISIBLE_SHARED` | `UPSTREAM-SRC-01`, `ACQ-A`, `ACQ-B`, `OBS-A`, `OBS-B` | `UPSTREAM-SRC-01→ACQ-A→OBS-A`; `UPSTREAM-SRC-01→ACQ-B→OBS-B` | Both observation traces complete |
| `VISIBLE_DISJOINT` | `UPSTREAM-A`, `ACQ-A`, `OBS-A`, `UPSTREAM-B`, `ACQ-B`, `OBS-B` | `UPSTREAM-A→ACQ-A→OBS-A`; `UPSTREAM-B→ACQ-B→OBS-B` | Both observation traces complete |

The shared template should yield shared ancestor `UPSTREAM-SRC-01`. The disjoint template should yield `NO_SHARED_KNOWN_ANCESTOR` while keeping `statistical_independence_established=false`. The scorer-only event registry assigns each visible template once to SAME and once to DIFFERENT, with no event key or source-family label added to either template. Within each template, the paired method-input JSON bytes must be identical.

## Boundary probes outside the 2×2

The contract suite also exercises missing/incomplete graphs, root-ID-only declarations, exact duplicate claims, conflicting reuse of node/edge IDs, unverified or conflicting trust, future-known evidence, expired evidence, missing edge endpoints, and cycles. These probes validate fail-closed states; they are not additional factorial cases or independent statistical samples.

## Execution and scoring contract

1. Freeze this protocol, canonical visible inputs, and the scorer-only registry hashes before calls.
2. Call only the versioned lineage contract on the two visible graph templates and freeze/hash all outputs.
3. Verify SAME/DIFFERENT twins are exact byte clones; if not, stop event-label interpretation and mark the identifiability check invalid.
4. After output freezing, read the scorer registry. Report the four graph assessments and clone checks.
5. Score only contract-state conformance to the registered visible graph assertions. Report event identity as `NOT_SCORED_UNIDENTIFIABLE` for all four cases. Do not compute false-merge, false-split, event accuracy, statistical independence, or superiority rates.

If comparing association behavior later, retain `TIME_ASSET_RULE` and `MULTI_EVIDENCE_RULE` outputs and hashes as the unchanged baseline. Any association method that consumes this contract must use a new arm name such as `MULTI_EVIDENCE_RULE_LINEAGE_V1`; do not silently rewrite or relabel the old rule. This draft itself executes no association rule and demonstrates no efficacy gain.

## Limits

The synthetic graph only represents lineage facts explicitly included in its input. An omitted shared cause, an incorrect completeness assertion, or compromised provenance can invalidate the interpretation. No common ancestor in this fixture is not evidence of statistical independence. No device, model, notification, paid service, or held-out data is involved.
