# MME v2 可执行设计

MME v2 将研究对象固定为 27 个物理种子与事件拓扑块。每块运行八种方法，共 216 个方法终态槽位，但独立统计单位始终是物理块，`n=27`。方法、事件、三个配对分支及其时间前缀均是块内重复观察，不能增加样本量。D01-D06 只开发和验证机制；D07 技术验证通过前不得运行 `MME_v2` 分析实验。

## v1 差异与研究范围

v1 的 15 个 P 块和 12 个 E 块原样保留，因子水平和块标识不改。v2 增加 `ES-Rebuild`，研究面板固定为 `Proposed, B1, B2, ES-Rebuild, B0, B3, B4, B5`。正式七臂 API 不随研究面板扩展而改变。运行类别固定为 `D_impl_unit`、`D_development` 和 `MME_v2`，三者使用不同种子域和输出目录；测试或开发结果不得改名混入 MME 样本。

当前公共表示只支持同一方向的简单支持：质量 `s` 落在目标命题，剩余质量落在全集。因此它不能诚实表示一般冲突。v1 中 `low/high/directional` 冲突标签在 v2 只保留为边界块的描述性分层和实现压力标签，不能产生“已验证一般冲突”的结论。若以后扩展一般冲突，必须另行记录固定辨识框架、合法焦元、质量归一校验、组合规则与跨方法共同输出，再生成新版本事件和结果。

## 公开事件与真值边界

事件生成器从块规格和冻结种子生成公开图 `G_D` 与独立物理真值侧车 `G_T`。方法只能取得 `MethodPrefix.method_payload()` 返回的 JSON 值；物理根、真等价边和有效控制集合只存在于 `PhysicalTruthSidecar`。公开对象与侧车只通过不可解释的 64 位十六进制哈希标识连接。事件标识、消息标识、根标识、排序和文件名均不得编码物理身份、未来控制或尚未披露的等价。

每块有三个配对分支：`X` 是基础证据，`XD` 是 `X∪D` 的重复扰动，`XI` 是 `X∪I` 的独立信息扰动。每个分支都保留逻辑时刻 0、1、2、3、4 的累积前缀，共十五个 `MethodPrefix`。前缀只含 `public_at` 不晚于观察时刻且全部引用对象已经出现的控制。`pre_commit` 表示等价控制在 XD 的重复初始化之前排序但同在首次可观察的 XD 前缀；它不会在 X 的更早前缀预告未来根。`post_commit_short` 在重复初始化之后于同一逻辑前缀披露，`post_commit_long` 在时刻 2 披露并保留后续观察。E06 的 delayed disclosure 在时刻 3 披露，时刻 4 提供披露后的恢复观察。

公开 `actions` 直接使用生命周期 JSON 边界：证据为 `INITIALIZE`，含 `action_id, op, order, message_id, version, root_id, support, reliability`；控制含 `action_id, op, order, roots`，并按操作增加 `canonical_root` 或 `replacement_root`。为基线适配保留等价的 `events` 和 `controls` 投影，但任何实现不得从侧车补全公开动作。方法 payload 不含 `block_id`、`arm_id`、`prefix_index` 或语义化 `prefix_id`；runner 在方法进程之外绑定这些评分元数据，方法只见不可解释的 bundle、transaction、事件和控制标识。

## 独立 oracle

`mme_oracle.py` 不导入生产方法、`LifecycleEngine`、生产 ledger、DST 或方法注册表。它对每个已经观察到的前缀同时给出两个结果：全信息 oracle 使用物理真值 `G_T` 对当前已出现事件归类，但不会读取未来事件；公开可知 oracle 只使用精确消息身份和该前缀已披露的控制。披露前可以计算方法相对全信息真值的偏差，却不能要求方法提前知道等价。恢复误差的义务从有效公开控制第一次出现的前缀开始。

手算锚点固定如下：单个 `0.80` 简单支持得到风险区间 `[0.80,1]`；两个公开独立的 `0.80` 根组合为 `0.96`；若它们物理上重复，全信息 oracle 在披露前仍为 `0.80`，公开可知 oracle 为 `0.96`；晚到等价披露后公开可知值恢复为 `0.80`。基础 `0.80` 与一个真正独立的 `0.80` 根应为 `0.96`。supersede、retire 和错误合并分别检查替换、移除以及公开声明与物理真值分歧，错误合并不能改写全信息物理类别。

## 共同输出与评分

八种方法共同输出 `method_id, status, risk_interval, action_state, failure_code`。合法简单支持的共同风险区间是 belief/plausibility `[s,1]`。行动阈值在执行前固定为 `0.70`：下端点不低于阈值时为 `ACT`，否则为 `REVIEW`。错误行动、无行动、崩溃、OOM、timeout 和无效输出保留具名终态，不补零、不丢行。

主指标为风险区间两个端点偏差、有效披露后的逐前缀恢复误差和行动集合分歧。belief L1 与 Jousselme 只对通过固定框架、焦元、非负、归一和有限值校验的实际质量函数计算；只有 risk score 或 Fréchet 区间的方法记为 N/A，并从该辅助指标分母排除。点输出只有与公共风险尺度同义时才可写为退化区间。

DRI 在同一块、同一逻辑前缀比较 XD 与 X，重复扰动下越低越好。SRI 在同一块、同一逻辑前缀比较 XI 与 X，并与全信息 oracle 的响应方向和幅度比较；SRI 表示独立信息响应，不能按数值越大越好评分。no-harm 窗口固定覆盖 X 和 XI 的五个前缀。良性可用性损失、误阻断增加和错误方向行动增加为 0，以及受限决策延迟增加不超过 1 个逻辑时刻，都是执行前固定的描述性参考线，不是已经验证的安全阈值，也不能把主比较不支持改判为支持。27 块的 P99 只描述样本，不形成尾部保证。

## 失败、复现与停止条件

块内方法顺序固定为预注册顺序，事件顺序由块种子在查看输出前决定。技术失败重试保留旧 attempt，使用同一块种子和输入；不得选择性重跑、换种子或覆盖失败。对科学问题、一般冲突表示、统计设计或数据范围的修改必须产生新预注册版本，新旧版本结果不能混合。

D02 的验收以独立测试证明：改变 truth sidecar 不改变方法 payload；公开披露时点改变可见前缀；开发种子与实际种子不同；十五个前缀完整；0.80/0.96、晚到等价、独立根、supersede、retire 和错误合并锚点成立；oracle 源码没有生产实现导入。D07 以前的运行只限 `D_impl_unit` 与 `D_development` 验证，不产生 MME 机制结果。

## 因子能力矩阵

P01-P15 保留 v1 的四因子行，但因子能力按实际公开表示解释。`distinct_key_same_acquisition` 使用不同消息和根标识，`derived_view` 另带公开 `derived_from` lineage，`exact_retry` 重复同一消息、版本和根，因此三类在方法输入中可区分。exact retry 的身份在到达时已经公开，不存在另行披露等价的时点，所以该类行中的 `pre_commit/post_commit` 标签只保留为原设计分层，不能计作等价时点覆盖。E01 缺边、E02 伪边、E04 错误拆根、E05 错误并根、E06 延迟披露、E07 过期边、E09 eventifier 过拆、E10 eventifier 过并、E12 超 cap 都有改变公开动作或真值关系的实际扰动。E03 只实现缺失等价所造成的可观察两根后果，不能外推为任意超边结构。E11 实现近 cap 的生命周期路径，但 `high conflict` 仍只是诊断标签。E08 的 context mismatch 缺少已定义的上下文本体，标记为 `NOT_IMPLEMENTED_SCOPE_BOUNDARY`，其槽位必须保留为不适用或未实现，不能计入“27 种因素均已支持”的覆盖声明。

资源 cap 是块内公开条件，所有方法相同。nominal 为 1,000,000 个活动类，E09-E11 的 cap-near 为 2，E12 overflow 为 1。E09-E11 的公开路径达到但不越过 2，E12 的独立根使活动类达到 2 并越过 cap 1；失败终态和后续 replay 均需保留。

## 预先固定的结论规则

主比较块固定为 `P01, P03, P08, P09, P10, P12`，覆盖有效的 post-commit distinct-key 或 derived-view 目标路径。只有六块的全部必需方法槽位和指标均有效，且 Proposed 相对 B1、B2 在风险区间端点误差与披露后恢复误差两个指标上分别至少有 4/6 块方向更优，才记为 `MECHANISM_SUPPORTED`。槽位完整但未达到该规则记为 `MECHANISM_UNSUPPORTED`；任一必需槽位或指标缺失、无效或不可比记为 `EVIDENCE_INSUFFICIENT`，不得删掉失败后重算。如果 Proposed 与 ES-Rebuild 在全部主比较值上以绝对容差 `1e-12` 相同，即使满足前述相对 B1/B2 的机制规则，也必须同时写明“未证明相对强重建基线的独特增量”。no-harm 参考线只并列报告，不改变主结论。

E12 的预期 cap 失败单独判定：八方法都应在首次超过 cap 1 的前缀产生具名活动类 cap 终态，并保留其后所有前缀槽位；这表示边界测试成功，不表示正常方法输出成功。E09-E11 的意外 cap 失败、E12 的提前失败、crash、timeout 或无效输出仍是实现失败。

27 块是确定性设计矩阵，不宣称随机独立同分布抽样。种子只生成不可解释标识和固定顺序，简单支持强度使用预先固定的手算锚点；因此首轮结论只属于这组机制与边界覆盖。
