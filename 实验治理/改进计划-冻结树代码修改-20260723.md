## 0. 目标与非目标

- 目标：消除 P1-4/P1-5 两处语义虚标与偏袒性特判；把"完整面板"与"单一哈希口径"两条不变量落为机械强制；清理 P2/P3 中低风险机械项；重封基线后恢复 runtime_gate=PASS。
- 非目标：不改任何方法的数学语义（B0–B5、Proposed 的 risk 计算逐位不变）；不动 Gate B 证据链协议；不动 schema 的字段语义（仅当批次 C 明确列出的字段）。

## 批次 C：证据语义矫正（预计 1–2 天，含 schema 影响评估）

**C1. 资格证据去自签发（P1-4）**
- `MethodSpec` 增加构造参数注入 `qualification_evidence_sha256: str | None`，内建 `_BUILTINS` 一律传 `None`；`formal_eligible` 维持现有推导（evidence 非 None 且为 hex64），于是**默认 False**；
- `_spec()` 中现在自算 qualification hash 的代码块改名为 `registration_commitment_sha256`（保留：它作为"实现+语义+schema+scorer 绑定"的注册承诺仍有价值，只是不再冒充资格证据）；
- 新增 `methods/qualification.py`：`qualify_registry(evidence_document) -> dict[str, MethodSpec]`——校验外部资格文档（每方法一条，绑定 implementation_sha256/semantics_sha256/output_schema_sha256/scorer_sha256）后，用 `dataclasses.replace` 返回携带 evidence 的 specs；
- `gate_evidence.refresh_runtime_freeze` 流程新增产物 `outputs/runtime_gate/method_qualification.json`（含逐方法承诺与文档自哈希），A1 证据由它 + 富注册表共同构成。
- 受影响测试：`test_gate_a_methods_adversarial.py:16`（恒等式两侧语义变为真实条件，测试文本不变仍应通过）；凡断言 envelope `formal_eligible is True` 的用例改为经 `qualify_registry` 的注册表执行，未资格化路径断言 False。
- ⚠️ envelope 字段 `formal_eligible` 的取值随之变化 → `method_output.schema.json` 不需改（布尔仍是布尔），但 `method_outputs_7of7.json` 证据需用资格化注册表重新生成。

**C2. 单一哈希口径（P2-2）**
- `MethodSpec.execute`（registry 层）**不再写 `result_sha256`**；
- api 层 `_PublicSpec.execute` 保持现状（补 `scorer_binding` 后对除 `result_sha256` 外全体求哈希）——它成为唯一 result hash authority；
- `methods/__init__` 已只导出 api 层，无需改；registry.py 模块 docstring 去掉 "public execution API" 字样，`run_method/run_all/get_*` 加下划线或 docstring 标注 internal；
- 受影响测试：grep `result_sha256` 于 tests，凡直连 registry 层断言该键的用例改走 api 层。

**C3. runtime_gate 注册表证据升级为富文档（P2-3）**
`gate_evidence` 写 `method_registry.json` 处改为落 `api.generate_registry_document()` 全文（含 per-method implementation/semantics/registration 承诺 + `registry_sha256` 自哈希）。
连锁：`registry_sha256` 值变 → `runtime_baseline.json`、`RuntimeCommitmentAuthority`、Gate B 各 fixture（`test_gate_b_purge*.py:60/66`、`test_gate_b_closeout_audit.py:75`、`test_gate_b_regeneration_hardening.py:51` 等以 `{"methods": list(METHOD_IDS)}` 构造假注册表的地方）需同步换成富文档构造器（建议提测试工具函数 `tests/_registry_fixture.py`）。这是本计划里连锁面最大的一项，安排在最后动。

**C4. truth isolation QA 如实化（P2-4）**
- `truth_isolation_qa.json` 生成器：4 个词法用例字段改挂 `lexical_guard` 名下；新增两个**结构性**负测：(i) 方法子进程收到的 stdin 全文与 `safe_observations` canonical 字节一致（不含 truth 参数任何派生）；(ii) 构造 truth 放入改名键（如 `gt_label`）证明词法层放行、但 runner 调用链上方法侧仍拿不到 scorer 的 truth 参数（只能证明传参路径分离，如实措辞）；
- 顶层字段改名：`scorer_only_truth_isolation` → 保留但语义注释为"结构分离设计 + 词法防护双证据"，新增 `lexical_guard_pass` 与 `structural_isolation_pass` 分列。
- `_TOKENS` 黑名单误伤面（withdraw/strawberry 类）在 QA 文件中登记为已知限制，不改行为（fail-closed 方向不动）。
